1. What this script is (and is not)

This script is a helper that runs in Google Ads every morning. Its job is to find search queries that are a bad fit for a collision / body shop, and then block those exact queries so the ads stop showing for that same search again on that campaign.

It is made for shops that want to:

  • Cut waste from cheap / glass / mechanical / competitor / junk searches
  • Do that automatically, without a spreadsheet Hub or Spoke
  • Get a short email that lists what was blocked
What it does not do
  • It does not change bids, budgets, or ads.
  • It does not add keywords you want to target (only negatives to block).
  • It does not write to shared negative keyword lists.
  • It does not use Hub or Spoke sheets.
  • It is not the metrics Engine. The Engine only reads data and updates sheets.

2. The big idea in plain words

Think of Google Ads like a store window. People walk by and type what they want.

Some people type things your body shop wants (example: “collision repair near me after accident”).

Some people type things that usually waste money (example: “cheap paint near me”, “oil change”, “Safelite windshield”).

This script looks at the last seven completed days of search queries that already showed ads. The window ends yesterday and overlaps on purpose so terms that Google publishes late are retried. If a query looks like junk under the rules, it adds that full query as an exact negative on the same campaign that showed it.

Tiny story

Yesterday someone searched cheap auto body near me and saw your Search campaign. That search had clicks or impressions but no conversion. The script sees the word cheap, checks that the query is safe to block, and adds this exact negative on that campaign:

[cheap auto body near me]

Next time someone searches that exact phrase, that campaign should not show.

3. What actually gets added in Google Ads

QuestionAnswer
What is added? The whole search query, as an exact negative keyword
Where is it added? On the campaign that generated the query (Search or Performance Max)
Account-level negatives? No
Shared lists? Not written (only read so it does not double-add)
Does it add the bare word “paint”? No. The trigger word only decides which queries to look at. The negative is the full query, like [cheap paint special near me]
Remember the brackets
In Google Ads, exact negatives look like [this exact phrase]. That means only that exact search (with small matching rules Google already uses) is blocked — not every search that merely contains one word inside it.

4. What happens on a normal morning run

Clock fires the MCC script → reads CONFIG.ACCOUNT_ALLOWLIST → finds up to 50 shops not finished yet today → for each shop, in parallel: look at the rolling seven completed days of Search + PMax terms match junk rules skip converters / already blocked / protected phrases add exact campaign negatives → stamp a “done today” label on shops that finished cleanly → email a reconciled summary + decision-audit CSV
  1. Pick shops. Only Account IDs on the allowlist can run.
  2. Pick campaigns. Inside those shops, only campaigns whose names include Built by Shah are scanned or updated. Other campaigns in the same account are left alone.
  3. Skip shops already done today. Finished shops get a label like BbsStandaloneNeg:2026-08-20.
  4. Read seven completed days (each shop’s own time zone), always ending yesterday, for Search and Performance Max terms that had impressions.
  5. Score each query against the rule list (cheap, glass, oil change, and so on).
  6. Pass safety checks (no conversions, not already covered, not too long, etc.).
  7. Add the full query as an exact campaign negative.
  8. Email the audit: adds, matched safe skips, reconciled decision counts, and a CSV that includes NO_RULE terms.

5. Safety checks before it adds anything

A query is only added when all of these are true:

  1. The campaign name includes Built by Shah (case-insensitive).
  2. The shop is on ACCOUNT_ALLOWLIST.
  3. The query showed ads in the last seven completed days (impressions).
  4. At least one junk rule matches (a trigger word/phrase is in the query).
  5. No rule exception saves it (example: “accident bumper repair” can be spared from the bumper rule).
  6. No protected phrase is present (shop name, or phrases you listed).
  7. No conversions in the seven-day action window, and no conversions in about the last 30 days.
  8. Google has not already marked the term added/excluded.
  9. An existing campaign or attached shared-list negative does not already cover it.
  10. The cleaned query is short enough for an exact negative (about ≤80 characters and ≤10 words).
  11. The campaign can be found and the negative can be created.
If something goes wrong for a shop (or it hits the safety ceiling), that shop is not stamped done for the day, so the next wave/run can try again.

8. What it usually leaves alone

  • Real collision / insurance language on many minor-damage rules (example: “accident bumper repair” can be spared from BUMPER_MINOR).
  • Your shop’s Google Ads account name (always protected).
  • Phrases you list in PROTECTED_PHRASES or per-account overrides.
  • Queries that already converted in the seven-day action window or the 30-day history guard.
  • Major insurer intent. AAA is context-aware: AAA insurance, claim, approved-body, and collision searches stay protected; mechanical junk such as “aaa auto repair” can still be blocked.
  • Queries already covered by an existing campaign or attached shared-list negative.
  • Geo / city + body shop (example: “yonkers auto body shop”, “collision repair dallas”) are kept. Clear named competitors (possessives like “steve's auto body”, multi-word brands like “sure shot collision”, or seed/COMPETITOR_PHRASES names) can still be negatived. Ambiguous one-word leftovers are left alone on purpose.
Keep examples (often spared)
  • “honda accord collision insurance claim” — insurance/claim language protects several rules
  • “accident bumper repair” — accident exception on bumper rule
  • “auto body repair near me” — may avoid GENERIC_CAR_REPAIR because of “body”

9. How you turn shops on and off

  1. Paste the script at the MCC.
  2. Fill CONFIG.ACCOUNT_ALLOWLIST with Account IDs (dashes OK).
  3. Fill CONFIG.EMAIL_RECIPIENTS.
  4. Optional: disable rules, protect phrases, or add local competitors in CONFIG / ACCOUNT_OVERRIDES.
  5. For shops that already have history, run the one-time backfill first (next section).
  6. Authorize, Run once, then schedule the daily sweeper at 7:00 AM Pacific or later.

Include a shop: add its ID to the allowlist.
Stop a shop: remove its ID from the allowlist.

10. Catch-up for old search terms (one-time backfill)

The daily sweeper retries the last seven completed days. That recovers late-published recent terms. It is not enough if a shop has already been advertising for weeks and old junk search terms were never blocked.

There is a separate one-time script for that catch-up: scripts/built-by-shah-mcc-standalone-backfill-negatives-sweeper-final-v1.1.0.js

  • It uses the same junk rules and the same allowlist idea.
  • It only touches campaigns whose names include Built by Shah.
  • It looks at about the last 90 days of Search + PMax search terms (not just yesterday).
  • When a shop finishes cleanly, it gets a permanent label like BbsStandaloneNegBackfill so a re-run skips it.
  • The email subject says Backfill (90-day) so you do not confuse it with the morning daily email.
  • If a shop or campaign is only 15–20 days old (or any span shorter than 90 days), that is fine. The script uses whatever history exists. Empty early days are not an error.
Simple workflow
  1. Run backfill once (and a second wave if you have more than 50 shops).
  2. When every allowlisted shop is stamped / the queue email is empty, stop.
  3. Then install and schedule the daily sweeper forever.
  4. Do not leave the backfill script on a Daily schedule.

11. Why you may need two schedules (50-account limit)

Google only lets one script run work on 50 accounts at a time. If your allowlist has about 70 shops:

  • Make a second Scripts row with the same code and allowlist.
  • Schedule e.g. 7:00 and 8:00 AM Pacific. Google normally finishes prior-day Search terms around 6:00 AM in each account’s local time.
  • Wave 1 labels finished shops; wave 2 takes the rest.
  • You get two emails that morning. That is normal.

12. The morning email

After each wave you get an HTML email (same visual style as the Hub Engine status email) with:

  • How many accounts ran
  • How many exact negatives were added
  • Raw Search/PMax row counts, unique campaign terms, and terminal decisions that reconcile
  • Per shop: channel (SEARCH / PMAX), campaign, [exact negative], rule IDs
  • Matched-but-skipped terms with the exact safe reason
  • A bounded CSV attachment with every retained unique term, including NO_RULE rows
  • Failures, if any

13. If a negative was a mistake

  1. Open that Google Ads account.
  2. Open the campaign → Negatives.
  3. Delete the exact match that should not be there.

There is no Spoke “Remove” checkbox in this standalone version. You undo by hand in Google Ads.
