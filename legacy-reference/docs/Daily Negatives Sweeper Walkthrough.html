Daily Negatives Sweeper Walkthrough

Built by Shah — what the Search (and PMax) negative keyword sweeper does every day

Audience: Account managers and ops
Scripts: Search sweeper + optional PMax sister sweeper
Not the Engine: This is a separate MCC Google Ads Script. It does not live inside the metrics Engine.
Guide in repo: docs/Read this for the Search negatives sweeper - auto-add review and remove on the spoke.md

1. One-sentence summary

Every scheduled day, the sweeper looks at the last seven completed days of search terms for each enabled shop, finds low-value queries that match your body-shop rules, adds the full query as an exact-match campaign negative, logs it on that shop’s spoke Negatives Audit tab, and (if an AM checked Remove earlier) deletes those flagged negatives on the next run.

2. How it fits the Hub-and-Spoke system

PieceRole for negatives
Hub Config On/off per shop, due-queue stamp, rule overrides (disable rules, protect phrases, local competitors)
Search / PMax sweeper scripts MCC scripts that read the Hub, change Google Ads negatives, write the spoke audit tab
Spoke Negatives Audit Per-shop log of what was added; AM marks Reviewed / Remove
Engine Metrics + goal sync only — does not add negatives
Both switches required for a shop to run:
Hub Enabled = Enabled and Hub Negatives Sweeper Enabled = Enabled and Spoke Spreadsheet URL filled in.

3. What happens on a normal daily run

Example: you schedule the Search sweeper Daily at 7:00 AM Pacific (and again at 8:00 AM for shops 51–70).

MCC Scripts clock fires → main() opens Hub → finds shops due today (≤50) → runs those shops in parallel → for each shop: Remove flagged rows → scan seven completed days → add exact negatives → write spoke → stamps Hub “Negatives Last Successful Run” when the shop finished cleanly

Step A — Wake up and read the Hub

  1. Opens the Hub spreadsheet URL from script config.
  2. Makes sure Negatives columns exist on Config (can append missing ones).
  3. Builds the candidate list of shops where:
    • Enabled is on
    • Negatives Sweeper Enabled is on
    • Spoke Spreadsheet URL is present
  4. Keeps only shops still due today: Negatives Last Successful Run is blank or not today’s date (PMax uses its own stamp: Negatives PMax Last Successful Run).
  5. Sorts by Priority (higher first), then Account ID.
  6. Takes up to 50 shops (Google’s hard parallel limit).

Step B — Process each shop (in parallel)

For every selected shop, the script switches into that Google Ads account and does the following.

Step C — Remove pass first (undo yesterday’s bad blocks)

  1. Opens that shop’s spoke → Negatives Audit.
  2. Finds rows where Remove is checked, Status is ADDED, and Channel matches this script (SEARCH or PMAX).
  3. Deletes that exact campaign negative from Google Ads.
  4. Updates the row to Status REMOVED and fills Removed At.
  5. Does not clear your Reviewed / Remove checkboxes or AM Notes.

Step D — Pull the rolling seven-day search-term window

  1. Uses the Google Ads account time zone (not UTC).
  2. Looks at the most recent seven completed days, always ending yesterday.
  3. Re-reading recent days is intentional. Google normally finishes prior-day Search terms around 6:00 AM in the account’s local time, so late-published terms get another chance on later runs.
  4. Also loads about 30 days of history for conversion guarding and lookback spend.
  5. Search sweeper: Search campaigns only.
  6. PMax sweeper: Performance Max campaigns only (same spoke tab, Channel = PMAX).
  7. Only terms with at least 1 impression are considered.

Step E — Match against the rule brain

Each search term is checked against the shared rule list (examples):

  • Minor / low-intent themes: dent, bumper, paint, scratch, ding, detailing, tint, glass, coupon, cheap, etc.
  • Many rules have exceptions (example: “dent” + “insurance” is protected for that rule).
  • CHEAP: cheap / cheapest / cheaply
  • LOCAL_COMPETITOR: seed chains + Hub Negatives Competitor Phrases
  • Hub can disable rules per shop via Negatives Disabled Rule IDs
  • Hub Negatives Protected Phrases plus Client Name / Account Name block auto-negatives on brand / specialty queries

Matching is word-boundary aware (example: “glass” does not match “fiberglass”).

Step F — Safety gates before any Ads change

A matching term is still skipped if any of these are true:

GateMeaning
Converted in action windowHas primary conversions in the rolling seven completed days
Converted in lookbackHas primary conversions in the ~30-day guard window
Already ADDED / EXCLUDEDGoogle already marks the term as added or excluded
Already coveredAn existing campaign or attached shared-list negative already blocks it
ProtectedEvery matched rule was exception-protected or Hub-protected
Too longWould exceed Google’s 80-character or 10-word keyword limits → logged as MANUAL_REVIEW, not added

Step G — Add exact campaign negatives

  1. Sorts remaining candidates by spend (worst waste first).
  2. For each eligible term, adds the full search term as an exact negative, like [cheap auto body near me].
  3. Adds at campaign level (not ad group).
  4. Never auto-adds bare trigger words as broad or phrase negatives.
  5. Does not write into shared negative lists (it only reads them for coverage checks).
  6. Processes all eligible terms in that run (no “only 10 per campaign” product cap).
  7. Keeps a high runaway safety ceiling (~500 adds per account per run). If hit, the shop is not stamped done so the next wave can finish the rest.

Step H — Write the spoke Negatives Audit tab

For each actionable result, a new row is written under the header (newest on top) with:

  • Date, Channel, Campaign, Search Term, Exact Negative, Matched Rules
  • Impressions, Clicks, Cost Yesterday, Cost Lookback, Conversions
  • Spend Summary (short blurb like “$12.40 lookback / $3.10 yesterday / 0 conv”)
  • Decision + Reason
  • Empty Reviewed / Remove checkboxes for the AM
  • Status such as ADDED, MANUAL_REVIEW, FAILED, or REMOVED

Step I — Stamp the Hub due queue

If the shop finished successfully and did not hit the safety ceiling, the script stamps today’s date on:

  • Search sweeper → Negatives Last Successful Run
  • PMax sweeper → Negatives PMax Last Successful Run

That shop is then skipped until tomorrow (unless you clear the stamp to force a re-run).

4. What the account manager does each day

  1. Open the shop spoke → Daily Checklist → Negatives audit status.
  2. Open Negatives Audit.
  3. Scan new rows (spend summary helps prioritize).
  4. Check Reviewed when the add looks correct.
  5. Check Remove if the negative was a mistake — the next sweeper run deletes it in Google Ads.
  6. Shop-specific rule tweaks (glass shop, local competitor, protect a phrase) happen on the Hub, not on the spoke.

6. Scheduling reality (~70 shops)

Google only allows 50 accounts per script run. With about 70 shops, schedule the same sweeper code at least twice daily (two Scripts rows, identical code, same Hub URL — for example 7:00 and 8:00 AM Pacific). Do the same separately for PMax if you install that sister script. Do not create a second Hub.

7. What this script never does

  • Does not live inside the Engine
  • Does not dump all shops’ negatives into one shared Sheet
  • Does not auto-add broad/phrase bare trigger words
  • Does not write shared negative lists
  • Does not use a DRY_RUN / LIVE mode switch (Hub Enabled columns control whether a shop runs)
  • Google Preview still never changes Ads if someone clicks Preview

8. End-of-day mental model

Hub decides who is allowed to be swept and which shop-specific exceptions apply.
Sweeper finds junk queries from the rolling seven completed days, adds exact campaign negatives, and logs them.
Spoke is where the human double-checks and can request a Remove on the next run.
